# 通讯协议与诊断边界

本文档说明 RKA-3000 通信测试工具当前实现的串口协议、探测顺序和判定规则。寄存器地址来自随代码钉定的协议模块；设备手册、现场接线和串口参数仍以实际设备为准。

## 统一行为

- 工具先由操作员选择串口，再按设备协议打开串口并逐个探测地址；刷新串口列表不会打开或发送任何设备帧。
- 每轮扫描只允许一个后台任务。取消是有界请求：当前读操作结束后，驱动在 `finally` 中关闭串口，任务才进入 `cancelled`。
- 串口读写均配置超时。响应必须经过帧校验才能作为有效数据；TAIE 的在线判定以 PV 为准，补充读取 SV 的失败单独记录。
- UI 的 `online`、`offline`、`degraded`、`error` 是设备结果；任务的 `completed` 只表示这一轮已经完成并清理了资源。

| 设备 | 传输 | 地址范围 | 扫描判定 |
| --- | --- | ---: | --- |
| TAIE 温控仪 | Modbus RTU | 1–247 | PV 读成功为 `online`；PV 超时为 `offline`；PV 成功但 SV 失败仍为 `online` 并附诊断 |
| Azbil MFC | MQV CPL over RS-485 | 1–127 | PV、SP 与实时量程均有效才为 `online`；PV 超时为 `offline`，PV 协议异常为 `error`，PV 有效但 SP/量程失败为 `degraded` |
| GS-CPA 天平 | ASCII 行，只听；O1 需勾选 | 单设备 | `G S` 稳定克重为 `online`；`Exx` 为 `error`；仅有不稳定、应答或未知帧为 `degraded`；收到字节却解析不出为 `degraded`；一个字节都没有为 `offline` |
| 龙腾协议天平（JD 格式与 ST 帧头格式） | ASCII 行，按需发送打印命令 `P` | 单设备 | 带 `g` 单位的稳定帧为 `online`，结果注明帧格式；`Err` 为 `error`；仅有不稳定、非克单位、回显或未知帧为 `degraded`；收到字节却解析不出为 `degraded`；发 `P` 后仍一个字节都没有为 `offline` |
| 天平去皮测试 | ASCII 行 | 单设备 | 去皮后读到稳定零点为 `online`；`Exx`/`Err` 为 `error`；无稳定零点为 `degraded`；去皮后无数据为 `offline` |

表单初始为 19200 bps 8N1（TAIE 的常用设置，选 TAIE 时不改动）；选 Azbil MFC 时填入 8E1（只能是 8E1 或 8N2）；选电子天平时按协议填入 GS-CPA 1200 bps 8N1、龙腾 2400 bps 8N1（龙腾 JD 出厂值）。以上均可修改。

## TAIE Modbus RTU

### 帧和串口

TAIE 使用标准 Modbus RTU，默认 19200 bps、8 数据位；校验位、停止位、超时由配置传入。请求和响应均为二进制帧，CRC-16/MODBUS 低字节在前：

```text
请求读保持寄存器：
[从站地址][03][起始地址高][起始地址低][数量高][数量低][CRC 低][CRC 高]

正常响应：
[从站地址][03][字节数][数据...][CRC 低][CRC 高]
异常响应：
[从站地址][83][异常码][CRC 低][CRC 高]
```

驱动会拼接分片读取、校验从站地址、功能码、字节数和 CRC；功能码 `03` 的异常码 `01/02/03` 分别表示非法功能、非法数据地址和非法数据值。扫描设置 `read_retry_attempts=0`，每个寄存器请求只尝试一次，保持扫描耗时和诊断次数明确。

### 扫描读取

| 名称 | 寄存器 | 解释 |
| --- | ---: | --- |
| PV | `0x008A`（十进制 138） | 过程值；按有符号 16 位整数除以 10 解码为温度 |
| SV | `0x0000` | 设定值；同样按有符号 16 位整数除以 10 解码，仅作诊断补充 |

每个从站先读 PV，再尝试读 SV。PV 超时生成 `offline`；PV 已响应而 SV 不可读时仍保留在线结论，并在 `detail` 中注明 SV 失败。扫描器不会调用 `write_single_register` 或 `write_multiple_registers`。

## Azbil MFC CPL

### 串口与帧

Azbil 只接受两种串口格式：`8E1`（偶校验、1 停止位）或 `8N2`（无校验、2 停止位），地址为 1–127。CPL 帧使用 ASCII 命令和二进制定界符：

```text
STX(0x02) + 地址(2 个 ASCII HEX) + 子地址("00") + "X"
      + 命令数据 + ETX(0x03) + 校验和(2 个 ASCII HEX) + CR LF
```

读取命令为 `RD` 加 4 位寄存器地址和 4 位字数；写入命令为 `WD` 加 4 位寄存器地址和每个数据字 4 位 HEX。校验和是从 STX 累加到 ETX 的低 8 位的二进制补码，再编码成两个大写 ASCII HEX 字符。响应必须包含正确的地址、固定子地址、`X` 标记、CRLF、校验和以及完整的 16 位寄存器字。

### 扫描读取与量程

扫描只使用读取命令：

| 名称 | 寄存器 | 说明 |
| --- | ---: | --- |
| 当前 SP | `0x04B6`（1206） | 当前使用中的设定流量 |
| 当前 PV | `0x04B7`（1207） | 瞬时流量，作为基础在线信号 |
| 满量程 | `0x03EA` | 实时设备量程原始值 |
| 小数位 | `0x03EB` | `decimal_position - 1` 为实际小数位数 |
| 流量单位 | `0x03ED` | `0` 为 mL/min，`1` 为 L/min |

PV 响应后，工具强制重新读取实时量程元数据，再检查满量程为正且不超过 `0xFFFF`、小数位在 1–6、单位码为 0/1，并确认 PV 和 SP 都位于 `0..full_scale_raw`。校验通过后才换算 `pv_lpm`/`sp_lpm` 并标记 `online`；元数据或 SP 失败标记 `degraded`，但保留已收到的 PV 原始值。工具不调用 CPL 写入命令，因此不会修改设定流量、功能参数或 EEPROM。

## 电子天平：共同规则

GS-CPA 与龙腾两种协议共用同一个探测流程，区别只在发送什么命令和怎样解析一行：

- 串口按行读取，以 `LF` 分行，解码为 UTF-8 并去掉首尾空白；每次读取受「超时」限制，最多读取「读取帧数」行。空行、未知行和读超时都计入这个次数。
- 驱动在解码前统计收到的字节数，并把收发字节以 DEBUG 级别写入通信日志（`发送: …`、`接收: …`），与 Azbil 驱动一致。
- 只有单位为 `g` 的稳定读数才算克重，并判定 `online`；第一帧稳定克重出现即结束本次扫描。
- 读到错误帧（GS-CPA 的 `Exx`、龙腾的 `Err`）立即判定 `error`。
- 收到的帧如果能被另一种协议解析成读数（例如选了 GS-CPA 却收到 `+00100.001  g` 或 `ST,-0045.578  g`），结果直接提示改选该协议。
- 扫描从不发送去皮命令；去皮只在下文的去皮测试中、经操作员确认后发送。

各协议实际发送的命令：

| 协议 | 扫描 | 去皮测试 | 从不发送 |
| --- | --- | --- | --- |
| GS-CPA | 默认不发送；勾选后开始发 `O1\r\n`，结束发 `O0\r\n` | 同扫描，另发一次 `T \r\n` | — |
| 龙腾 | 打开后发一次 `P\r\n`，之后每次读超时（一个字节都没收到）再发一次 | 同扫描，另发一次 `T\r\n` | `O`（开/关）、`C`（校准）、`M`（模式），以及 GS-CPA 的 `O1`/`O0` |

## GS-CPA 天平

GS-CPA 使用带 CRLF 的 ASCII 行。工具在配置勾选“开始连续输出”时发送 `O1\r\n`，扫描结束或取消时在串口仍可用的情况下发送 `O0\r\n`；默认不发送启动命令。

| 收到的行 | 解析结果 |
| --- | --- |
| `+0012.34 G S` | 稳定读数，克 |
| `+0012.34 G U` | 不稳定读数 |
| `Axx`（如 `A00`） | 应答 |
| `Exx`（如 `E01`） | 错误 |
| 其他非空行 | 未知帧 |

未勾选连续输出时，工具不向天平发送任何内容，只接收天平主动输出的数据。龙腾天平的 `O` 是开关命令，因此一个字节都收不到时，结果先提示「龙腾天平请改选龙腾协议、不要勾选 O1」，再提示 GS-CPA 天平可勾选 O1 重试。

## 龙腾协议天平

龙腾协议读取两种已实测的天平，两者都接受 `P`、`T` 命令并回显：

| 天平 | 一帧示例 | 行尾 | 详细文档 |
| --- | --- | --- | --- |
| 龙腾 JD 系列 AⅡ版 | `+00100.001  g` | `CR LF` | [龙腾 JD 系列电子天平](longteng-jd-balance.md)：说明书串口参数、输出方式、命令和 2021 年记录 |
| 带 ST 帧头的天平（型号待确认） | `ST,-0045.578  g` | `CR LF LF` | [带 ST 帧头的电子天平](balance-st-header.md)：2026-11-11 实测和两者对照 |

在线结果的说明会注明读到的是「龙腾 JD 格式」还是「ST 帧头格式」，现场可据此确认接的是哪台天平。

| 收到的行 | 解析结果 | 依据 |
| --- | --- | --- |
| `+00100.001  g`、`+0010.0000 g` | 稳定读数，单位取 3 位单位字段 | JD 说明书 §6.1，2021 年记录 |
| `+00100.001`（单位字段全为空格） | 不稳定读数 | JD 说明书 §6.1 |
| `+00012.000pcs` | 稳定读数，单位 `pcs`，不算克重 | JD 说明书 §6.1 的单位字段 |
| `ST,-0045.578  g` | 稳定读数 | 2026-11-11 实测 |
| `US,+0001.234  g` | 不稳定读数 | 同类帧头的通行约定，**未实测** |
| `ST,12.345`（无单位） | 稳定读数，按克 | 上游 `balance-serial` 早期示例 |
| `O`、`T`、`C`、`M`、`P` | 命令回显，记作应答 | JD 说明书 §4.2；`T`、`P` 的回显两种天平均已实测 |
| `Err` | 错误 | JD 说明书 §4.2 |
| 空行 | 忽略，但算收到了数据，不触发 `P` | ST 帧头天平的 `CR LF LF` |
| 其他（如回显与帧相撞的 `TT,-0045.565  g`、从帧中途开始的 `566  g`） | 未知帧 | 2026-11-11 实测 |

龙腾 JD 出厂为 2400 bps、8N1（参数 `C4-0`），输出方式为命令控制（`C5-2`）：不按打印键也不收到 `P` 命令时，天平不发送任何数据。因此扫描在打开串口后发送一次 `P`，之后每次读超时再发一次；命令输出和连续输出两种设定都能读到数据。`P` 等同打印键，只请求一组读数，不改变零点、模式或参数，扫描仍是只读的。连续输出时 `P` 至多多出一行回显。

## 天平没有数据时的判定

解码会丢弃非法字节，波特率错误时整行可能变成空白，因此不能用「没有帧」代表「线路没有信号」：

| 情况 | 状态 | `values` | 下一步 |
| --- | --- | --- | --- |
| 一个字节都没收到 | `offline` | `bytes_received: 0` | 龙腾：已发 `P` 仍无响应，核对波特率（JD 出厂 2400）、串口号和直连线（2-2、3-3、5-5）；GS-CPA：先确认不是龙腾天平，再勾选 O1 重试 |
| 收到字节但解析不出帧 | `degraded` | `bytes_received`、`last_rx_hex` | 核对波特率、校验位和停止位 |
| 解析出帧但没有稳定克重 | `degraded` | `observed`（最近 5 行） | 等待称重稳定；确认单位是 `g`；按提示确认协议是否选对 |

## 天平去皮测试

去皮会改变天平零点，因此是独立于扫描的任务：只在操作员点击「去皮测试」并在确认框中同意后，由 `POST /api/tare` 启动，不参与自动复查，与扫描共用单任务互斥。

| 协议 | 去皮命令 | 确认依据 |
| --- | --- | --- |
| GS-CPA | `T \r\n` | 可能先回 `Axx`；须随后读到 `G S` 稳定零点 |
| 龙腾 | `T\r\n` | 回显 `T`（可能与帧相撞或丢失，不作依据）；读超时时用 `P` 请求读数；须读到带 `g` 的稳定零点 |

执行顺序：

1. 打开串口；GS-CPA 勾选连续输出时先发送 `O1`；龙腾发送一次 `P`。
2. 最多读取「读取帧数」行，记录第一条稳定克重为 `before_g`（尽力而为，读不到也继续）；龙腾在读超时时再发 `P`。
3. 清空串口输入缓冲，避免去皮前已缓存的零点帧被误当作确认；发送一次去皮命令。
4. 去皮命令发送完成后，开始「去皮等待」（1–30 秒，默认 5 秒）确认阶段。逐行读取，每行之间检查取消，龙腾在读超时时发 `P`；每个字节的读取超时取串口超时与剩余等待时间的较小值，持续无换行数据也不能延长总期限。读取结束后再次检查截止时间，到达或超过截止时间的帧只保留作诊断，不用于确认成功：
   - 稳定重量且绝对值不超过「零点容差」（默认 0.05 g）→ `online`，记录 `after_g`；
   - `Exx` 或 `Err` → `error`（天平拒绝去皮）；
   - 只有不稳定或非零读数 → `degraded`，记录最后读数 `after_g`；
   - 只有应答（`Axx` 或回显 `T`）没有称重帧 → `degraded`；GS-CPA 提示启用 O1 后重试，龙腾说明已发 `P` 仍无称重帧，不建议 O1；
   - 只有未知、无法解析或到达截止时间的响应 → `degraded`，保留最近响应供诊断；
   - 什么都没收到 → `offline`；收到的字节解析不出帧 → `degraded`，与上一节的判定相同。
5. 无论结果如何，已发送 `O1` 时在 `finally` 中发送 `O0` 并关闭串口。

去皮命令发出前取消不会发送去皮命令；发出后取消只停止等待，不能撤销天平上已经生效的去皮。「去皮等待」只限制发送命令后的确认阶段，不再额外等待一次完整串口读超时；基线采集、命令发送和串口清理另计耗时。基线最多读取配置的帧数，每次使用独立的串口读取超时。

## 错误、超时与安全边界

- 串口打开失败、驱动异常和未预期异常统一生成为 `error`，详细异常只写入日志和任务结果。串口被其他程序占用（Windows 上为 `PermissionError`「拒绝访问」）时，说明直接写明被占用，并保留原始异常。
- 单次读超时范围由配置限制为 0.05–10 秒；天平扫描最多调用 1–100 次按行读取，空行、未知行和读超时都计入次数。取消会等待当前协议探测与串口清理结束，不承诺在单个超时周期内返回。
- 业务 API 只监听 `127.0.0.1`，每次桌面启动生成随机 Bearer token；协议帧不会经由网络转发。
- 扫描是只读探测：不下发 TAIE 设定值、不写 Azbil 寄存器、不执行天平去皮。唯一改变设备状态的路径是需要操作员确认的天平去皮测试。GS-CPA 的 `O1/O0` 是为读取连续输出服务的可选会话控制，且只在用户明确勾选时执行；龙腾的 `P` 等同打印键，只请求读数。
- 真机验收仍需核对型号、地址、波特率、线序、终端电阻、量程单位和设备手册；软件测试使用假串口或帧样例，不能替代现场验证。
