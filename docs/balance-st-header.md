# 带 ST 帧头的电子天平（型号待确认）：现场实测

本文记录 2026-11-11 用串口调试助手实测的一台电子天平。它的帧带 `ST,` 状态头，行尾是 `CR LF LF`，与 [龙腾 JD 系列 AⅡ版](longteng-jd-balance.md) 说明书和 2021 年记录的格式不同，按另一个型号处理。**品牌和型号尚未确认**，确认后请补到本文标题和下一节。

这台天平能接受龙腾 JD 的 `P`、`T` 命令并回显，本工具用同一个「龙腾」协议读取，两种帧格式都能识别；扫描结果的说明会标出读到的是哪种格式。实现见 `src/rka_comm_tester/_vendor/balance_serial/protocols/longteng.py`。

## 与龙腾 JD 的区别

| 项目 | 龙腾 JD AⅡ版 | 本型号 |
| --- | --- | --- |
| 一帧示例 | `+00100.001  g` | `ST,-0045.578  g` |
| 帧头 | 无，以符号位开头 | `ST,`（稳定） |
| 整数位 | 5 位（0.001 g 型号） | 4 位 |
| 稳定判定 | 单位位全为空格表示不稳定 | 帧头 `ST` 表示稳定 |
| 行尾 | `CR LF`，每帧 15 字节 | `CR LF LF`，每帧 18 字节 |
| 连续输出间隔 | 约 200 ms（说明书写约 0.3 s） | 186–219 ms |
| 连续输出时发 `P` | 未在连续输出下测试；命令输出方式下回显 `P` 并返回一组读数 | 至多回显一行 `P`，不多出读数帧 |
| `T` 的回显 | 单独一行 `T` | 可能与正在发送的帧相撞，如 `TT,-0045.565  g` |
| 依据 | 说明书和 2021 年记录 | 仅本文的实测 |

现场判断方法：看调试助手或通信日志里的接收字节。以 `53 54 2C`（`ST,`）开头的是本型号；以 `2B`（`+`）或 `2D`（`-`）开头、以 `67 0D 0A`（`g CR LF`）结尾的是龙腾 JD。

## 已知的串口行为

| 项目 | 取值 | 依据 |
| --- | --- | --- |
| 波特率 | 2400 bps | 实测时的设置；其他可选值未知 |
| 数据位 / 校验 / 停止位 | 未记录，测试工具按 8N1 打开 | — |
| 输出方式 | 测试时为「连续稳定输出」 | 用户设置；面板参数名未记录 |
| 帧格式 | `ST,` + 符号 + 4 位整数 + `.` + 3 位小数 + 3 位单位字段 + `CR LF LF` | 十六进制实测 |

```text
53 54 2C 2D 30 30 34 35 2E 35 37 38 20 20 67 0D 0A 0A
 S  T  ,  -  0  0  4  5  .  5  7  8 ␠  ␠  g CR LF LF   → -45.578 g，稳定
```

| 部分 | 含义 |
| --- | --- |
| `ST,` | 状态头，`ST` 表示稳定 |
| `-0045.578` | 符号、4 位整数、3 位小数 |
| `␠␠g` | 3 位单位字段，右对齐 |
| `CR LF LF` | 多一个换行，按行读取时每帧之后会多出一个空行 |

本工具的处理：

- `ST,` 帧为稳定读数；单位缺省时按克处理，兼容上游 `balance-serial` 早期示例 `ST,12.345`。那个示例可能就来自这一类天平。
- `US,` 帧按这类帧头的通行约定当作不稳定读数，**尚未实测**。
- 其他帧头（包括相撞产生的 `TT,`）记为未知帧丢弃。
- 空行算作收到了数据，不会触发打印命令 `P`。只有一个字节都没收到时才发 `P`。

## 实测记录

均为 2026-11-11，用串口调试助手接在测试电脑上。

### 14:12 连续稳定输出，未发命令

秤盘处于去皮后取下物品的状态，读数稳定在 -45.578 g。

- 14:12:06.854 至 14:12:12.263 以十六进制接收，每帧都是上面那 18 字节。
- 14:12:12.453 至 14:12:18.066 切回 ASCII 显示，内容相同；多出的 `LF` 显示为空行。
- 帧间隔 186–219 ms。

### 15:38 连续稳定输出下发送 `P` 与 `T`

接收按 ASCII 显示。

| 时间 | 发送 | 收到 | 说明 |
| --- | --- | --- | --- |
| 15:38:19.168–24.390 | `50 0D 0A`（`P`）共 7 次 | 5 次在 109–234 ms 后看到单独一行 `P`，在相邻帧之前或之后；另 2 次（20.743、23.734）只多出一个空行，没有看到 `P` | 帧节奏不变，也不多出一帧 |
| 15:38:40.860 | — | `566  g` | 接收从一帧中途开始，残缺行应丢弃 |
| 15:38:42.297 | `54 0D 0A`（`T`） | 约 190 ms 后 `TT,-0045.565  g` | 回显 `T` 与正在发送的帧相撞，帧头 `S` 丢失，这一帧仍是去皮前的重量 |
| 15:38:42.483–42.905 | — | 约 0.4 s 无输出 | 天平执行去皮 |
| 15:38:42.905 起 | — | `ST,+0000.000  g` | 去皮完成，约 0.6 s 后回零 |
| 15:38:44.608、45.666、46.684 | `T` 共 3 次 | 约 110 ms 后单独一行 `T` | 读数已为零时的回显，零点保持不变 |

结论：

- 回显和数据帧共用一条线路，可能出现在帧前、帧后，可能和帧撞成残缺行，也可能看不到。不能依赖回显来确认去皮；本工具以去皮后读到的稳定零点为准。
- 去皮从发命令到回零约 0.6 s，远小于工具默认的 5 s 去皮等待。
